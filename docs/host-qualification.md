# Mobile host qualification

Status: pending on Omarchy and physical iPhone/iPad. The development host used for the artifact CLI was arm64 macOS.

1. Prepare a clean, dedicated non-root Linux account with no sudo or container socket access. Give it one fixture checkout and the tools needed to build it. Record the OS version and architecture independently for x86_64 and arm64.
2. Review [OmarchyRemote at the evaluated revision](https://github.com/gigq/OmarchyRemote/tree/573d40722d227d3067ae98d8f4c93e67d4380b6c), including the upstream installation commands, systemd units, listener configuration and dependency locks. Start the reviewed units under that account with the listeners on loopback. Use the [OmaBridge gateway](gateway.md) with verified host identity and per-device certificates. Omit public forwarding. Verify the app blocks unrelated peers before opening a terminal.
3. Enroll a physical device through the ingress's documented workflow. Confirm the expected hostname and certificate in Safari. Connect to the workspace over HTTPS, open a terminal, clone or open the approved fixture repo, edit a file and run its tests. Exercise touch input, modifier keys and a hardware keyboard if available.
4. Start a finite host job that logs progress and records its PID. For each lock, app background, and Wi-Fi-to-cellular transition, reconnect and verify the same PID and ordered output. Measure reconnect time, latency and resource usage. Also exercise overlapping sessions and expired credentials.
5. Produce a fixture build. Use a separate signing machine and publish both files to a download location scoped to the approved account. Download through the qualified device. Confirm the copied artifact with the CLI and the independently provisioned key and expected build ID. Repeat after interruption and with a modified download. Track in-device verification as a separate acceptance item.
6. With the terminal active, revoke the phone's network admission. Require denial of further input and output on that socket and denial on reconnect. Confirm that an authorized second device can still connect. Test malformed protocol input defensively against the gateway's own validation tests, and verify the workspace cannot see another account's non-public files.
7. Save only measured results and versions, with no raw tokens or credentials. Remove the test ingress and stop the upstream user units when qualification ends. The pinned upstream README has service removal instructions.
